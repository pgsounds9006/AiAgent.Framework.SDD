# AiAgent.Framework.SDD

*`README.md`를 옮긴 문서입니다. 원본이 권위를 가지며, 두 문서가 어긋나면
영어 원본을 따릅니다.*

소프트웨어 엔지니어링용 에이전트 스킬입니다. 판단 기준은 단 하나입니다.
**의미가 지금 어디까지 검증됐는가.** 어떤 기능이든 그 의미는 아직 모르는
상태, 알지만 약하게 표현된 상태, 굳어서 보호되는 상태 중 어딘가에
있습니다. 엔지니어링 조언이 서로 충돌하는 이유도 대개 여기 있습니다.
어느 위치를 전제하느냐에 따라 옳은 조언이 달라집니다.

크게 두 부분으로 나뉩니다. `SKILL.md`가 커널이고, 단계와 무관하게
성립하는 것들을 담습니다. 진단은 가설로 다룹니다. 출처는 값을 고를
때가 아니라 계약으로 승격할 때 따집니다. 되돌리는 비용은 들인 노력이
아니라 외부 의존으로 잽니다. `references/sdd/`는 그 위에 얹은 정책
하나로, 세 모드(bootstrap, harden, distill)와 각 모드의 관점·권한·정지
조건을 정의합니다. 커널은 이 정책 없이도 성립하고, 저장소 이름도 커널을
묶지 않습니다. 같은 기준이 범위도 정합니다. 의미가 얼마나 검증됐는지와
상관없는 주제는 여기 들어오지 않습니다.

spec-driven development 안에서는 인식론 쪽을 맡습니다. 명세를 어떻게
쓰고 강제할지가 아니라, 명세에 들어갈 내용이 어디서 나오고 언제 굳혀도
되는지를 다룹니다. 자세한 논증은 `RATIONALE.md`에 있습니다.

## 무엇이 어디에 있나

실제로 설치되는 것은 전부 `src/` 아래 있습니다.

**내용**은 스킬 자체이고 `src/skills/software-development/`에 있습니다.
요약본 말고 이걸 읽으십시오.

**이유**는 `src/RATIONALE.md`에 적었습니다. 왜 기준이 하나뿐인지,
무엇을 일부러 뺐는지, 위험이 어디 있는지, 뭐가 아직 미해결인지를
다룹니다. 채택 전에도 설치 전에도 읽는 편이 낫습니다. 설치하다 보면
절차에 안 나오는 상황을 만나는데, 그때의 판단 기준입니다.

**절차**는 `src/INSTALL-SKILL.md`에 있습니다.

## 설치

에이전트에게 아래를 그대로 입력하십시오.

```
Read and proceed:
https://github.com/pgsounds9006/AiAgent.Framework.SDD/blob/main/src/INSTALL-SKILL.md
```

대개는 절차랄 게 거의 없습니다. SKILL.md 형식을 그대로 읽는 하네스라면
`src/skills/software-development/`를 로더가 보는 자리에 놓는 걸로
끝납니다. 절차가 따로 있는 건 그다음 때문입니다. 배치가 실제로
작동하는지 관찰하고, 그 과정에서 문제가 드러난 경우에만 브릿지를
만듭니다.

## 제거

에이전트에게 아래를 그대로 입력하십시오.

```
Remove AiAgent.Framework.SDD.
```

절차는 없습니다. 설치가 에이전트 눈에 안 띄는 걸 남기지 않기 때문입니다.
