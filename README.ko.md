# AiAgent.Framework.SDD

AiAgent.Framework.SDD는 소프트웨어를 개발하는 동안 불확실한 의미를 언제 열어두고, 언제 계약으로 고정하며, 언제 불필요한 구조를 정리할지 판단하기 위한 에이전트 스킬입니다.

일반적인 SDD 도구처럼 요구사항, 설계, 작업 목록 등의 산출물 형식을 정하거나 고정된 개발 절차를 제공하지는 않습니다. 대신 에이전트가 구현 과정에서 사실, 가설, 정책, 임시 선택, 외부 계약을 구분하도록 돕습니다.

핵심 원칙은 다음과 같습니다.

* 아직 확인되지 않은 의미는 성급하게 고정하지 않습니다.
* 검증된 의미는 적절한 계약으로 보호합니다.
* 의미를 더 이상 보호하지 않는 중복 구조는 정리합니다.

에이전트는 문제에 따라 조사, 설계, 구현, 검증 방식을 자유롭게 선택할 수 있습니다.

## 사용자에게 보이는 것

이 스킬의 내부 모드나 라우팅 과정은 일반적으로 사용자에게 설명하지 않습니다.

사용자에게 필요한 것은 어떤 프레임워크를 적용했는지가 아니라 다음과 같은 판단 내용입니다.

* 현재 확인된 사실
* 구현 과정에서 선택한 정책
* 아직 남아 있는 불확실성
* 해당 결정을 내린 이유
* 결과를 검증한 방법

내부 절차는 드러내지 않되, 판단의 근거는 설명하도록 설계되어 있습니다.

## 세 가지 사고 모드

`bootstrap`, `harden`, `distill`은 순서대로 진행하는 프로젝트 단계가 아닙니다.

각 기능, 계약, 구현 결정의 현재 상태에 따라 독립적으로 적용하는 사고 모드입니다. 하나의 시스템 안에서도 서로 다른 영역에 세 모드가 동시에 적용될 수 있습니다.

### Bootstrap

아직 의미가 충분히 확인되지 않은 경우에 사용합니다.

실제 동작을 관찰하고, 필요한 만큼만 구현하며, 검증되지 않은 가정을 공개 인터페이스나 장기 계약으로 고정하지 않습니다.

임시 값이나 로컬 구현을 사용할 수는 있지만, 그것을 외부에서 이미 확립된 사실처럼 다루지는 않습니다.

### Harden

의미가 확인되었고 이후 변경으로부터 보호할 필요가 있는 경우에 사용합니다.

확인된 의미를 타입, 스키마, 런타임 검증, 테스트, 프로토콜 등 적절한 형태의 계약으로 옮깁니다.

더 강한 계약이 기준이 되었다면, 같은 내용을 반복하는 자연어 지침이나 임시 검증 코드는 정리합니다.

### Distill

의미와 동작이 이미 충분히 보호되고 있는 경우에 사용합니다.

탐색 과정에서 생긴 임시 구조, 중복된 추상화, 더 이상 필요하지 않은 방어 코드와 설명을 제거합니다.

목표는 코드의 양을 줄이는 것이 아니라, 같은 의미를 더 명확하고 직접적으로 표현하는 것입니다.

## 예시

외부 서비스 연동에 페이지 크기 값이 필요하다고 가정합니다.

에이전트는 내부 기본값으로 `100`을 선택할 수 있습니다. 구현을 진행하기 위한 임시 선택에는 반드시 외부 근거가 필요하지 않습니다.

다만 실제 확인 없이 `100`을 외부 서비스의 최대 허용값이라고 문서화하거나 공개 계약으로 만들어서는 안 됩니다.

이후 실제 동작이나 신뢰할 수 있는 문서를 통해 해당 제한이 확인되고, 다른 코드나 사용자가 그 값에 의존하게 되면 스키마 제약이나 런타임 검증으로 보호할 수 있습니다.

그 뒤에는 같은 내용을 중복해서 표현하는 임시 설명과 검증 코드를 정리합니다.

이 과정은 구현을 지연시키기 위한 것이 아니라, 임시 선택과 확인된 계약을 구분하기 위한 것입니다.

## SDD와의 관계

명세가 개발을 이끌려면, 명세에 포함된 내용이 어느 정도의 근거와 권위를 가지는지 구분할 필요가 있습니다.

기존 SDD는 주로 명세를 작성하고, 설계와 작업으로 나누며, 구현과 연결하는 절차를 다룹니다.

이 프로젝트는 다음 질문에 초점을 둡니다.

> 명세에 포함된 의미는 어디에서 왔으며, 언제부터 이를 계약으로 다뤄도 되는가?

요구사항 문서, 설계 문서, 작업 생성기, 테스트 또는 다른 SDD 도구를 대체하지 않습니다. 이러한 산출물에 포함된 내용을 어느 정도의 확신으로 다뤄야 하는지 판단하는 보조 계층에 가깝습니다.

## 구조

이 스킬은 Kernel과 SDD policy로 구성됩니다.

### Kernel

`src/skills/software-development/SKILL.md`

Kernel에는 특정 개발 단계와 관계없이 적용되는 엔지니어링 원칙이 들어 있습니다.

* 진단은 검증되기 전까지 가설로 다룹니다.
* 값의 선택 자체보다, 그 값을 사실이나 계약으로 승격할 때 근거를 요구합니다.
* 확인된 사실, 선택한 정책, 임시 보상책을 구분합니다.
* 이미 투입한 노력보다 외부 의존성과 변경 비용을 중요하게 봅니다.

### SDD policy

`src/skills/software-development/references/sdd/`

SDD policy는 Kernel의 원칙을 `bootstrap`, `harden`, `distill` 모드로 적용합니다.

정책은 교체할 수 있으며, Kernel은 특정 모드 이름에 의존하지 않습니다.

### Rationale

`src/skills/software-development/references/rationale.md`

Rationale 문서에는 현재 구조를 선택한 이유, 의도적으로 제외한 범위, 알려진 위험과 미해결 문제가 정리되어 있습니다.

## 설치

```text
Read and proceed:
https://github.com/pgsounds9006/AiAgent.Framework.SDD/blob/main/src/INSTALL-SKILL.md
```

`SKILL.md` 형식을 지원하는 환경에서는 일반적으로 다음 디렉터리를 설치합니다.

```text
src/skills/software-development/
```

실제 설치 위치와 브리지 필요 여부는 설치 문서에서 확인할 수 있습니다.

## 제거

에이전트에게 다음과 같이 지시합니다.

```text
Remove AiAgent.Framework.SDD.
```

설치 과정에서는 에이전트가 찾거나 제거할 수 없는 별도의 숨겨진 상태를 만들지 않습니다.
